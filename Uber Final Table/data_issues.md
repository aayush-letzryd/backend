# Uber Final Table: Data Quality, Normalization & Remediation Catalog

This document details the data quality anomalies, edge cases, root causes, and production resolutions implemented for the Uber core transformation pipeline (`public.core_uber_daily` and `public.core_uber_weekly`).

---

### Issue Catalog

| Issue ID | Severity | Category | Symptom / Anomaly Description | Production Resolution |
| :--- | :---: | :--- | :--- | :--- |
| **UBR-01** | **Resolved** | Ingestion Schedule | Uber supplier feeds are retrieved asynchronously each morning. | Disentangled from raw tables; processed via `pg_cron` running every 30 minutes. |
| **UBR-02** | **Critical** | Missing Foreign Key | `uber_pipeline_order_transactions.vehicle_number` is 100% NULL from Uber Supplier API, and 27,057 rows have NULL `trip_uuid`. | Resolved via multi-tiered fallback cascade: `ot.trip_uuid -> t.car_no`, description plate regex `[A-Z]{2}[0-9]{1,2}[A-Z]{1,2}[0-9]{4}`, and driver-date active vehicle lookup. |
| **UBR-03** | **Critical** | Sign Inversion | `cash_collected` in raw order transactions is stored negative (min -₹7,023.62). Subtraction in SQL (`earnings - cash`) effectively added cash to earnings, inflating balances up to 100x. | Normalized via `ABS(cash_collected)` and correctly subtracted from earnings in `net_driver_day_balance`. |
| **UBR-04** | **Critical** | Case Sensitivity | Raw `trip_status` is lowercase `'completed'`, while previous SQL trigger checked uppercase `'COMPLETED'`. Over 95% of recent completed trips were zeroed out. | Normalized via `COUNT(*) FILTER (WHERE LOWER(trip_status) = 'completed')`. Restored 60,000+ completed trips. |
| **UBR-05** | **High** | Operational Cutoff | Documentation claimed 04:00 AM IST cutoff, but SQL code used `trip_date` (calendar date). Late-night rides (00:00 to 03:59:59) were misattributed to the next day. | Enforced in SQL: `((trip_request_time - INTERVAL '4 hours')::date) AS operational_date`, verified against Hisaab ground truth rows 244 vs 246. |
| **UBR-06** | **High** | Multi-Vendor Duplication | When a vehicle had multiple vendor codes in one settlement week, weekly milestone incentive from `uber_vehicle_incentives_raw` joined 1-to-many, doubling/tripling payouts. | Enforced ranking: `ROW_NUMBER() OVER (PARTITION BY vehicle_number, settlement_week ORDER BY trips DESC, active_days DESC) = 1`. Incentive credited strictly once per car. |
| **UBR-07** | **Critical** | Lock Contention & Triggers | Synchronous statement triggers on `uber_pipeline_trips` and `uber_pipeline_order_transactions` caused deadlocks, slow ingestion, and silent aborts. | **All triggers dropped from raw tables.** Zero overhead on raw ingestion. Processing migrated to background `pg_cron` job `sync-core-uber`. |
| **UBR-08** | **High** | Stalled Sync | Core table sync was frozen since September 16, 2026. September 17 and 18 were completely missing. | Stored procedure backfill executed for August 23 to current date; restored 17,000+ trips and all missing financial records. |
| **UBR-09** | **Medium** | Subscription Fee Parsing | `driver_subscription_charge` was hardcoded to `0.0` in live database function. | Restored regex and description parsing for Drive Pass, platform fees, and subscription charges. |
| **UBR-10** | **Critical** | Timezone Offset Inconsistency | `trip_request_time` is stored in IST (+05:30) while `reporting_time` is stored in UTC (+00:00). Applying `- INTERVAL '4 hours'` to UTC shifted the transaction cutoff to 09:30 AM IST. Over 47,000 morning trips (04:00 to 09:30 AM IST) had trips on Day D but earnings/cash attributed to Day D-1. Month boundaries and leap days dumped morning earnings onto the previous month/year. | Linked transactions now strictly inherit the trip's operational date `((t.trip_request_time - INTERVAL '4 hours')::date)`. Unlinked transactions convert UTC to IST before cutoff: `((ot.reporting_time + INTERVAL '1 hour 30 minutes')::date)`. |
| **UBR-11** | **Critical** | Partial Week Overwrite Corruption | In `sp_sync_core_uber`, `weekly_cal` filtered on `d.operational_date BETWEEN (v_start_date - INTERVAL '6 days') AND v_end_date`. When called with rolling lookback (e.g. 7 days), the start date fell mid-week, aggregating only partial days for the earlier week and overwriting complete week totals via `ON CONFLICT DO UPDATE`. Caused 843 trip mismatches and 873 earnings mismatches in Week 37. | Scoped weekly aggregation strictly to full ISO week boundaries: `operational_date >= DATE_TRUNC('week', v_start_date)::date AND operational_date <= (DATE_TRUNC('week', v_end_date) + INTERVAL '6 days')::date`. Completely eliminated all weekly mismatches. |
| **UBR-12** | **Critical** | Incentive Duplication (₹2.24 Cr) | `uber_vehicle_incentives_raw` contained duplicate ingestion rows across 18,008 vehicle-weeks (ingested with and without `org_uuid`). Procedure aggregated via `SUM(total_payout)`, doubling payouts across 6,710 vehicle-weeks and inflating weekly balances by ₹2,23,91,180.00. | Changed aggregation from `SUM(total_payout)` to `MAX(total_payout)` in `raw_inc_agg`. Accurately extracts true single-tier milestone payout and eliminates duplicate ingestion inflation. |
| **UBR-13** | **High** | Missing Indexes & Sequential Scans | `uber_pipeline_trips` (352k rows) and `uber_pipeline_order_transactions` (323k rows) lacked indexes on timestamp and date expressions. Every sync execution performed 3 full sequential scans and spilled 13MB+ sorts to disk. | Added 4 non-locking indexes concurrently: `idx_uber_trips_req_time`, `idx_uber_trips_op_date`, `idx_uber_txns_rep_time`, `idx_uber_txns_op_date`, and `idx_uber_txns_coalesce_op_date`. Scan execution dropped from sequential scans to sub-100ms bitmap index scans. |
| **UBR-14** | **High** | Platform Fee Double Deduction | For 5,423 Reserve Platform fees, `actual_earnings` was negative (-₹15.00) and `paid_to_you` was -₹15.00. The procedure included this negative amount in `net_fare_earnings` and also captured `ABS(paid_to_you)` in `driver_subscription_charge`, double-deducting the fee (-₹30.00) in `net_driver_day_balance`. | Excluded negative subscription/platform fees from `net_fare_earnings`. Fees are now deducted strictly once as `driver_subscription_charge`. |
| **UBR-15** | **Medium** | Cron Schedule Collision | `sync-core-uber`, `sync_core_ola_30m`, and `refresh_daily_vehicle_status_15m` all fired simultaneously at minute :00 and :30, causing connection spikes and lock contention. | Staggered `sync-core-uber` to `5,35 * * * *` (minutes 5 and 35). Completely eliminated concurrent job overlap. |
